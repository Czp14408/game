# 人工验收清单（第一阶段原型）

> 使用边界（2026-10-15）：本清单及勾选结果属于旧原型与后续注明日期的UI验收；890/21/128是历史执行记录，不是本次重跑结果。自由移动、金币探索收费等检查不适用于新版卡牌入口；新版交互需按[接入记录](新版节点首批接入-2026-10-14.md)及[当前核心规则](../design/游戏核心规则定稿.md)另行验收。旧勾选不代表新版已人工通过。

> 用途：只列**必须由人在有显示环境下做**的测试。
>
> 自动验证已覆盖（不必人肉重复）：无画面 **890 项断言**（含真实帧推进段）、真实帧循环 **21 项**、
> 真渲染 **128 项布局断言**。它们能证明「规则算得对、界面构得出来、布局不溢出」，
> 但证明不了「看着顺不顺、手感对不对、点得中不中、中文缺不缺字」——那部分在本清单。
>
> 用法：逐项打勾。不通过的写进最后一张记录表（现象 / 复现步骤 / 截图路径），交回即可。

## 0. 前置

启动（试玩包，**不需要编辑器**）：

```
dist/wudao_prototype/run_game.bat        开始游戏
dist/wudao_prototype/run_screenshots.bat 自动逐页截图（对照用，需要显示环境）
```

按键（已按 `project.godot` 实测核对，非文档推测）：

| 键 | 作用 | 生效范围 |
| --- | --- | --- |
| `W A S D` / 方向键 | 移动 | 小地图 |
| `E` | 与最近的交互点互动 | 小地图 |
| `Tab` | 打开大地图 | **仅小地图** |
| `B` | 打开构筑 | **仅小地图** |
| `Esc` | 战斗暂停 / 继续 | **仅战斗页** |
| `F` | 战斗中单步推进 | 仅战斗页 |
| 鼠标 | 点击按钮、大地图节点、小地图交互点 | 全部页面 |

两档分辨率用鼠标拖拽窗口右下角改到 1280×720 与 1920×1080 各做一遍。

## 附：文档与实现不一致、以及顺带修掉的问题

### 1. 大地图键位（已修实现）

`project.godot` 里 `open_world_map` 实际绑的是 **Backspace**（`physical_keycode 4194308`），
而 `README.md` 与页面按钮都写「**Tab**」。人工试玩的第一反应「按 Tab 没反应」就是这个原因。
已改为 `Tab`（`keycode 4194306`），并加了 9 项按键断言（M4/M5 由 99→108）防止再回归。

### 2. `Esc` 与 `Tab`/`B` 的生效范围（已定案）

原 README 写「`Esc` 关闭界面/战斗中暂停」，但代码里**只有战斗页**处理 `Esc`（暂停）。

已按两条处理：

- **`Tab` 改为大地图开关**（2026-10-07 试玩反馈）：小地图按 `Tab` 打开大地图，
  在大地图上再按 `Tab` 收起回小地图。原先「只能打开、不能收起」的单向行为已去掉。
  实现：`page_world_map.gd` 增加 `_unhandled_input`；页面按钮文案也标为「返回小地图（Tab）」。
- **`Esc` 不改交互，只把文档改如实**：`Esc` 仍只在战斗页生效（暂停/继续）；
  商店、构筑、战前用页面内按钮返回；`B` 仍只在小地图生效。

因此：**在商店／构筑／战前按 `Esc` 无反应是预期行为**（见 C10），不是缺陷。
若之后想让 `Esc` 全局生效，可在 `AppRoot` 加一层路由（商店→关闭、构筑→关闭、大地图→关闭），约 20 行。

### 3. 顺带修掉的「无画面不可测」问题（2026-10-07）

为了让 Tab 开关能被自动验证，暴露出两个只在无画面脚本模式下出现、却会**吞掉键盘输入**的问题：

- **`is_inside_tree()` 在该模式下恒为 false**——实测连 `SceneTree.root` 自己都是 false
  （`root_inside=false app_inside=false holder_inside=false`）。页面 `_unhandled_input` 开头
  正是这道守卫，于是键盘输入被全部丢弃，键盘路径此前根本无法自动验证。
  已把守卫改为 `get_parent() == null or is_queued_for_deletion()`：语义更准（防的是
  「页面已被替换或正在释放」），且可测。
- **`get_viewport()` 在该模式下返回 null**，`get_viewport().set_input_as_handled()` 会报
  `Cannot call method 'set_input_as_handled' on a null value`。已在 `PageBase` 增加带保护的
  `consume_input()`，6 处调用点统一改用。
- **`--script` 模式下不派发布局**（2026-10-07 补记）：控件 `size` 恒为被设置的尺寸，
  量不到容器重排后的实际矩形。战斗页事件日志正是被这条漏掉的——换行 `Label` 被
  `ScrollContainer` 排成 **191×1 像素**，同步断言看到的是「设定值 328」而不是「实际 1」，
  于是 779 项全通过却整块日志区空白，直到看真渲染截图才发现。
  已改用自带滚动的 `RichTextLabel`，并把 4 条日志断言放进无画面套件的**帧推进段**
  （`extend_with_frames`）——那一段有真实帧循环，量得到实际矩形。
  教训：**凡「容器会不会把子节点压扁」这类问题，必须放在帧推进段或真渲染截图里守。**
