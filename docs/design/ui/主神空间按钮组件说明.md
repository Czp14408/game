| 图集 | 排列与用途 |
| --- | --- |
| `action_states.png`（历史参考图，当前工作区缺失） | 三行四列：第一行主操作，第二行普通操作，第三行危险操作；各行从左到右为默认、悬停、按下、禁用 |

## 统一原则

- 小切角矩形、细浅蓝轮廓、半透明数字底板、像素边缘、宽松内容留白。
- 主操作淡填充，用于开始、挑战和确认；同一操作区避免多个按钮同时强调。
- 普通操作更通透，用于治疗、购买、整理和返回。
- 危险操作以暖红提示，用于丢弃或主动认输；保留操作文字及必要确认，不能只靠颜色识别。
- 悬停边框更亮，按下底色稍深，禁用降低对比度；选中模式增加下沿指示。
- 图标和文字在 Godot 中单独叠加，保持清晰，不跟随底板一起降低透明度。

## 透明度检查与接入限制

三张图集外角抽样 alpha 为 0，具有透明外部。主操作内部抽样 alpha 157（约62%不透明），普通操作26（约10%），危险操作116（约45%）；模式默认内部抽样17，图标默认内部157。数值为局部抽样，不代表整张图恒定。

主操作和图标底板比此前确认的背包横栏更实，接入时建议先将这两类底板控件 alpha 设为约0.5—0.65，再在主神空间背景上校准。普通按钮和模式按钮需重点检查背景较亮时的辨识度。不要降低包含文字或图标的父控件透明度。

生成图集的框体位置与尺寸存在细微差异，个别外围有发光像素、内部有轻微纹理。当前属于待校准的视觉模板：还需配置有效纹理区域，统一外框尺寸、减少边缘杂点，并检查真实缩放效果，不能宣称已完成生产接入。

## 接入规格建议

| 类型 | 逻辑显示尺寸起点 | 内容留白 |
| --- | --- | --- |
| 主／普通／危险按钮 | 高40—48，宽随文本和布局 | 左右16—20，上下8—10 |
| 模式按钮 | 高36—40，宽按模式名确定 | 左右12—16 |
| 图标按钮 | 36×36或40×40 | 图标周围8 |

长按钮以九宫格方式伸缩，切角保持尺寸；方形图标按钮保持比例。鼠标交互区域使用规则矩形，不随发光像素变化。状态切换不改变布局尺寸。文本、图标和键盘焦点框独立显示，焦点不能仅由悬停状态替代。

## 模板名称与图集对应

以下名称用于文档与后续接入配置，不代表工程已经存在同名 API。图集行列从 1 开始，定位依据可见按钮区域，不直接等分整张画布。

| 模板名称 | 来源 | 对应功能性质 |
| --- | --- | --- |
| `primary` | action_states 第1行 | 开始、挑战、重新开局等页面主要推进动作 |
| `secondary` | action_states 第2行 | 购买、出售、装备、治疗、打开页面、返回等常规动作 |
| `danger` | action_states 第3行 | 丢弃物品、主动认输、危险确认 |
| `mode` | mode_states | 当前模式、职业血统选择、商店锁定等持续选择状态 |
| `icon` | icon_states | 关闭、设置、展开等小型图标操作 |

`primary`、`secondary`、`danger` 和 `icon` 的列1—4依次为 `normal`、`hover`、`pressed`、`disabled`。`mode` 列1—5依次为这四种状态及 `selected`。

功能类型决定模板，鼠标与业务状态决定图集状态。不要根据按钮文字长度、页面颜色或当前金额随意换功能模板。

### 主神空间整备

对应现有 [page_deity.gd](../../../godot_prototype/scripts/ui/pages/page_deity.gd)。

| 功能标识 | 显示文字 | 模板 | 行为入口 | 可用条件／反馈 |
| --- | --- | --- | --- | --- |
| `deity.heal` | 免费治疗 | secondary | `ctrl.deity_heal()` | 处于主神整备且生命未满；满血显示“生命已满”，接入时使用禁用态；免费回满，不恢复失败次数 |
| `deity.shop` | 主神商店 | secondary | `ctrl.open_shop(...)` | 有效试炼与主神商店上下文；打开当前主神商店，不远程查看其他商店 |

### 商店

对应 [page_shop.gd](../../../godot_prototype/scripts/ui/pages/page_shop.gd)，当前操作 ID 保持不变。

| 操作 ID | 显示文字 | 模板 | 行为入口 | 可用条件／反馈 |
| --- | --- | --- | --- | --- |
| `buy` | 购买 | secondary | `ctrl.buy_slot(index)` | 选中未售出的有效商品且余额足够；物品接收容量、技能学习资格仍由服务校验；失败不扣币 |
| `sell` | 出售 | secondary | `ctrl.sell(instance_id)` | 选中下排实际持有物品且在商店上下文；出售不是丢弃，不采用危险模板；提示回收价 |
| `refresh` | 刷新 | secondary | `ctrl.refresh_shop()` | 商店有效、未锁定且余额满足刷新价；刷新价从配置读取 |
| `lock` | 锁定／解锁 | mode | `ctrl.toggle_shop_lock()` | 商店有效；未锁定用默认态，锁定用选中态且文字改为“解锁”；锁定作用于整批商品 |

## 共用面板与按钮的关系

当前工程 [PanelInventory](../../../godot_prototype/scripts/ui/panel_inventory.gd) 接收物品行与操作数组，页面决定业务，皮肤决定显示。两行不是二十格背包容量：

| 使用场景 | 上排 | 下排 | 操作区 |
| --- | --- | --- | --- |
| 整理 | 十点战斗栏 | 十点背包 | equip / unequip / use / synth / discard / leave |
| 商店 | 当前商店商品，仍为四货位 | 十点背包待售物品 | buy / sell / refresh / lock / leave |
| 独立背包（待接入） | 不自动作为额外背包容量，复用内容先按具体范围配置 | 实际背包 | 仅显示背包上下文允许的操作，不提供商店交易 |

物品点选与模式选中是不同关系：物品格使用自己的品质与选择框，不能把整个物品格直接套成模式按钮。共享面板不携带金币、容量和商店规则。

## 状态与确认映射规则

1. 业务不可用时优先使用 disabled，不能点击，也不保留悬停或按下外观。原因通过提示或反馈区域解释。
2. 可用按钮鼠标按住时使用 pressed；悬停使用 hover；否则使用 normal。
3. 职业、血统、模式与锁定按钮保留 selected 状态。当前图集没有 selected-hover／selected-pressed，接入时在 selected 底板上叠加轻量悬停或按压反馈，保持选择标记可见。
4. 键盘焦点作为独立细线叠层，不等同于悬停；禁用按钮不能获得可执行焦点。普通瞬时操作不保留 selected。
5. 丢弃确认弹窗：显示物品名称、品质与不可回收提示；“确认丢弃”映射 danger，“取消”映射 secondary。
6. 认输确认弹窗：明确“结束当前试炼”；“确认认输”映射 danger，“继续试炼”映射 secondary。
7. 点击待确认危险按钮只打开确认，不先改变状态；取消不产生副作用，确认时重新校验目标仍存在。重复点击不得重复消耗或重复结算。
8. 购买、出售、治疗、装备、卸下、使用与刷新默认直接执行并显示结果，不新增逐次确认；合成沿用现有合法候选逻辑。
9. 服务层是最终裁决：页面显示为可用也必须再次校验，失败不扣币、不丢物、不移动半件物品。

## 接入配置约定

建议给现有操作数组增加可选的视觉属性，保持原有 `id` 和回调不变。字段是文档约定，尚未改代码：

| 字段 | 作用 | 示例 |
| --- | --- | --- |
| `id` | 页面内稳定的功能标识 | buy、discard、leave |
| `label` | 当前显示文字 | 购买、解锁、返回 |
| `variant` | 模板类别 | primary / secondary / danger / mode / icon |
| `disabled` | 业务可用状态 | true / false |
| `selected` | 持续选中状态，只用于相应控件 | 商店锁定或职业已选 |
| `disabled_reason` | 不可用说明 | 余额不足、生命已满 |
| `confirm_kind` | 危险确认类型 | discard / surrender；普通动作为空 |
| `align` | 操作区对齐关系 | left / right，沿用现有字段 |

同一个 `id` 在不同页面可有不同回调，例如 leave 在商店离开、在整理返回；完整配置使用页面范围区分。模板不存在或未配置时回退 secondary，不能回退成危险或主操作按钮。

图集裁框、九宫格与矩形信息通过 [UI 修改迭代工作流](../../guides/ui修改迭代工作流.md) 中的生成器／清单／访问层处理；页面不手写图集裁切坐标。业务映射放在页面或集中语义表，不能写进纹理访问层。

## 接入验收

主界面与信息页入口补充映射：点击右上角小地图打开信息页；面板关闭控件使用 icon，返回使用 secondary；信息页生命、金币、失败次数为只读信息，不能套用可点击按钮样式。小地图入口属于可点击地图组件，不使用按钮底板覆盖地图。信息页互斥、面板恢复和 Esc 关闭顺序以 [主界面与交互调整方案](../../history/early-prototype/游戏主界面与交互调整方案.md) 第5节为准。

快捷键同步映射：E 场景交互，B 切换背包／整理，M 切换信息页。B 再次按下关闭右侧面板，商店不随之关闭；M 再次按下关闭信息页并恢复此前有效面板。按钮关闭和对应快捷键关闭调用同一关闭流程，战斗限制优先，不能通过快捷键绕过。技能与物品掉落均在敌方物品栏正中间直接点击领取。

旧版独立阶段预览页的映射，现统一转入同一战斗界面的准备状态：查看对手通过卡牌悬停，开始战斗仍为 primary，调整构筑和准备状态返回仍为 secondary。战后掉落物直接点击拾取，不新增拾取、放弃或整理按钮；退出战斗使用 secondary，未领取默认放弃。战斗进行中不开放返回场景。

- 每个已列出的现有按钮可以查到模板、状态和原有行为入口；待接入入口不会被误记为已经完成。
- 商店锁定保持选择反馈并禁用刷新；解锁恢复正确状态。
- 未选中、满血、余额不足、无合成候选等情况下，不可用反馈符合业务结果。
- 丢弃与认输只有确认后执行，取消不改变状态；出售使用普通样式。
- 模式切换不新增背包容量或商店货位，不开放远程商店。
- 同一按钮切换状态时尺寸、位置不变；文字与图标不受底板透明度影响。
