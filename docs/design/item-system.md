# 物品系统设计与制作指南

> 规则优先级核对（2026-10-15）：本文维护已实现的物品编辑、导入和展示契约，不单独定义整作玩法。发生冲突时以[核心规则](游戏核心规则定稿.md)为设计依据，再安排实现适配；主题新效果列入内容设计不意味着本流水线已支持。

最后核对：2026-10-09。本文是物品系统唯一现行设计依据，覆盖 Excel、生成资源、获取渠道、战斗机制、卡面、悬停、动效及素材规范。完成情况和后续工作只维护在 [最新状态与进度](../status/item-system-status.md)。技能内容不在本流水线范围内。

## 1. 系统边界与数据流

`content/items.xlsx` 是全部物品定义及商店物品候选的唯一编辑来源。流水线为：专属图片 → Excel → 校验与模板展开 → 生成资源 → 游戏加载 → 预览与实际渠道验收 → 留档。

| 层次 | 文件或组件 | 职责 |
| --- | --- | --- |
| 编辑 | `content/items.xlsx` | 身份、四品质数值、机制快照、渠道和自身被动 |
| 素材 | `godot_prototype/assets/items/icons/` | 每件物品独立图片；框体与状态由 UI 叠加 |
| 编译 | `tools/import_items.py`、`item_special.py`、`item_channels.py` | 校验字段、补齐已支持模板、生成稳定版本 |
| 输出 | `godot_prototype/data/generated_items/` | `manifest.json` 和各物品 `.tres`；禁止手改 |
| 加载 | `ContentCatalog` | 读取生成定义、商店候选及奖励规则；缺少生成包时报错 |
| 战斗 | `ItemDef` → `BattleItemState` → `CombatEngine` | 定义共享；本场成长、冷却等放在战斗状态中 |
| 获取 | `ShopService`、`EncounterService`、`WorldService`、`QuestService` | 各渠道抽取和发放；库存操作由 `InventoryService` 管理 |
| 展示 | `ItemCard`、`ItemSkin`、`ItemCardLayout`、`ItemStatBadge`、`ItemMulticastBadge`、`ItemMotion`、`GamePalette` | 各页面复用卡片、悬停与状态展示 |

表中 `tools/` 指 `godot_prototype/tools/`。旧 `data/items/` 不再加载；`build_content.gd` 不生成物品，也不写商店物品候选。技能、敌人、地图、任务、商店概率仍由工程维护。敌人装备及基础剧情奖励可以引用物品 ID，但不能另存一套物品数值。

## 2. Excel 契约

物品 ID 须以小写字母开头，仅含小写字母、数字、下划线，发布后保持稳定。名称不用于关联。保留表头和列顺序，填实际值，不使用公式；明确的 `0` 与空白不同。禁用示例不生成，启用渠道必须引用启用物品。

| 工作表 | 一行含义与填写规则 |
| --- | --- |
| 物品总表 | 一件物品：ID、名称、类别、TAG、占格 1/2/3、可装备、模板 ID、版本、图片路径、启用、备注。TAG 用英文逗号分隔，不从名称推断 |
| 品质属性 | 每件物品青铜、白银、黄金、钻石各一行；冷却毫秒、价格覆盖、多重释放次数 |
| 效果配置 | 物品 ID＋效果 ID 的结构快照：顺序、事件、来源、动作、目标、TAG 筛选、包含自身、属性、持续范围、取值来源、参数键 |
| 效果数值 | 一个效果参数一行，横向填四品质；效果 ID 与基础模板的参数键可由工具补齐，组合附加属性须指定参数键 |
| 获取渠道 | 物品 ID、渠道类型、内容池 ID、权重、最低品质、最高品质、启用、备注 |
| 物品扩展 | 已有自身被动；仅支持空白或 `charge_on_weapon_use`，后者要求可装备 |
| 模板库／公共字典 | 模板目录与稳定 TAG、事件、动作等参考；增加词条不会自动实现机制 |
| 渠道字典 | 当前合法商店、敌人、容器、任务入口 ID |
| 填写指南／UI规范 | 填写辅助，不作为自由脚本或物品数值来源 |

四品质只改变数值，不改变名称、图片、TAG、效果类型、目标或顺序。当前冷却为物品共享字段，四档须相同并兼容 100 ms 战斗步长。战斗物品价格覆盖留空，沿用原价格规则。固定价非战斗物品四档填写相同非负偶数价格，冷却 0、不可装备、多重释放 1，四档基础值相同。

模板版本目前为 `1`。首次更新复制结构到物品自己的效果配置，已有快照不会随模板更新或模板 ID 改名而重写。换机制须显式修改快照。`custom` 必须提供完整且受支持的结构。自动补齐先完整校验，失败回退；写回前保留工作簿备份。只校验模式不写回。

## 3. 已支持机制

| 模板 | 类别 | 效果数值参数 |
| --- | --- | --- |
| `tpl_attack` | weapon | attack |
| `tpl_shield` | shield | shield |
| `tpl_poison` | poison | poison |
| `tpl_burn` | burn | burn |
| `tpl_heal` | heal | heal |
| `tpl_growth_attack` | weapon | growth、attack 两行 |
| `tpl_haste / tpl_slow / tpl_freeze` | haste / slow / freeze | 同名参数，持续时间毫秒，100 ms 整数倍 |
| `tpl_consumable` | consumable | value，战斗外恢复量 |
| `tpl_material` | material | value，材料基础值 |

基础数值为 `0–99999` 整数。加速目标为己方其他主动物品，减速与冰冻目标为敌方主动物品；首版控制模板只有一条效果。现有武器使用充能被动通过物品扩展维护。

### 基础组合

五种基础模板可在效果数值追加 attack/shield/poison/burn/heal 行，填写独立四档值；工具补齐缺少的效果配置，保留已有快照。小物品最多三种，中／大最多五种，同种属性不得重复，效果 ID 唯一，顺序连续且第一条对应物品主类别。

组合共用 CD 和多重次数。一次使用只计一次 uses 和 use_item，各效果发送各自事件（use_shield、heal、apply_burn、apply_poison 等）。仅武器类别的攻击发送 use_weapon，非武器附加攻击不享受职业武器伤害加成或武器使用被动。

效果表顺序不改写战斗阶段：双方锁定 → 护盾／治疗 → 攻击／旧异常跳伤 → 死亡检查 → 新异常／控制 → 连锁。新增异常不在本步立即跳伤，死亡时后续异常与连锁停止。被动直接获得护盾不等同使用护盾效果。

### 多重释放

品质属性 F 列填 `1–10`，空白默认 1。自然 CD 就绪且未冻结时，在同一步执行 N 次独立使用，CD 只重置一次；每次分别统计、发事件和结算效果。已有武器使用充能等监听也逐次响应。卡面显示单次值，不显示 N 次总和。多重释放与事件触发额外使用是不同机制，不能用次数字段隐式实现后者。

### 成长攻击

`tpl_growth_attack` 仅支持“全体武器成长＋攻击”两条结构，不追加其他基础效果。每次先提升己方战斗栏所有武器（包含自身），再读取当前攻击。未就绪或冻结的武器也接受成长，但不会因此立即使用。成长只存于本场状态，下场清零。

同一步按释放轮次处理：每轮汇总本侧参与物品的成长，再快照各物品攻击，排列不影响结果。基础 8、成长 5、×2 时分别攻击 13、18，合计 31，卡面最终显示 18。冻结的成长来源不触发；仅一次释放的物品使用第一轮快照，后续成长影响其下次使用。

### 新机制如何接入

未实现的事件监听、灼烧触发额外使用、自由表达式、永久成长、新目标等均拒绝导入。接入顺序：明确事件／动作／参数和防递归规则 → 实现战斗行为 → 验证边界 → 接入模板及导入校验 → 自动说明与展示 → 填表使用。仅往字典加名词不能完成机制。灼烧触发额外使用曾讨论，但尚未实现；是否继承多重次数须届时明确。

## 4. 获取渠道

不同渠道各占一行，同物品同类型同入口不能重复。权重为正有限数，表示候选相对权重，不是独立掉率。最低品质不得高于最高品质。

| 类型 | 当前入口 | 规则 |
| --- | --- | --- |
| shop | gear_shop、weapon_shop、clinic、deity_mixed、skill_shop | 先抽商店品质，再按允许候选权重抽物品；商店品质及类别概率由工程保留 |
| drop | bandit、bandit_chief、camp_blade、mountain_guard | 保留原 30% 材料／70% 装备技能分支；新候选加入后者，原条目权重 1 |
| event | material_small、supply_small | 保留原容器奖励，追加一件加权候选；重开不重抽、不重复发放 |
| quest | main_kill_chief、side_challenge、side_road_bandit | 保留原金钱奖励，追加一件加权候选，以 reward_id 防重复 |

非商店新增候选选中后，在所填品质范围内等概率选择。固定价非战斗物品只发青铜，范围须包含青铜。未配置新增候选时沿用原奖励路径。当前不支持数量、多件必得、独立触发概率或世界限定；备注不执行规则。event 只指现有容器，新剧情事件、敌人或任务须先在工程建入口。

例：`shield_dagger / drop / bandit / 1 / 青铜 / 白银 / 是`。同一物品也可另填 event 或 quest 行。

战后物品沿用待拾取结算。任务背包满时保存在 `RunState.pending_quest_items`，金钱及进度照常结算；库存提交后腾出空间自动重试入包，保持原抽取结果，不再发钱。该状态仅属于本次试炼，不新增磁盘存档。

商店实际品质是 Excel 范围与商店概率的交集。固定四品质预览不证明自然渠道出售四档。迁移统一候选后，旧种子的具体库存可变化；同一新内容版本内继续可复现。

## 5. 通用卡片与悬停

商店、背包、整理、小地图背包、战斗和掉落复用卡片。小／中／大宽高比为 `1:2 / 2:2 / 3:2`，尺寸由现有槽位决定，不增加状态栏滚动或过大最小尺寸。

- 每件物品使用独立图片，完整背景有效。当前图片等比例留边，不拉伸、不裁剪；旧物品缺图时显示文字。
- 同品质共用像素边框和选中框，32×32 九宫格框、切片 8；`assets/ui/item_frames_v1/theme.json` 管理图片内距 6、悬停内距 16、宽度 320。
- 顶部按攻击、护盾、中毒、灼烧、回复固定顺序显示数值，不加小图标，跨住上边框，单排且不侵入邻格。最大徽章 72×24，间距 2，上移 8；字号最大 16，按文本长度及空间缩小。
- 新配置数值最多五位。运行时超出范围显示“超限”，悬停显示真实值，不截断战斗计算。约 56 px 小卡同时三项五位数时字号很小，需要悬停阅读。
- 多重次数为 1 隐藏；其他次数以顶部中央小吊牌 ×2–×10 展示，位于属性牌下方。宽约卡宽 16%（14–28 px），高约卡高 12%（12–16 px），文字最多 10 px。
- 商店价格独立位于卡面下方，动效不遮挡数值和吊牌。

悬停顺序：名称 → TAG → 可选冷却 → 分隔线与自动效果正文。名称不加品质、不显示占格，品质由框体样式区分；TAG 统一文字色。正文支持攻击等统一属性图标，卡面数值不加图标。战斗中只更新最终值，不显示基础／成长拆分；成长说明先于攻击说明。多重次数另写“冷却结束后连续使用 N 次”。

## 6. 共用状态动效

`ItemMotion` 只读取真实战斗状态，不参与计算，不需逐物品填表。覆盖层裁切卡内、忽略鼠标，顶部数值和次数位于更高图层；非战斗页不启用。

| 状态 | 已确认表现 |
| --- | --- |
| CD | 暗幕从下向上褪去，水平边界细线与流动像素亮点；不显示下方进度条，保留剩余秒数 |
| 加速 | 白色为主、少量淡蓝的流光均匀快速上行，大小参差；自然推进 ×2 |
| 减速 | 相同流光形态改为棕色、缓慢下行；自然推进 ×0.5 |
| 冰冻 | 冰蓝框、淡蓝遮罩、错落大雪花和角部冰晶；自然 CD 停止，仍允许充能 |
| 充能 | 当前 CD 水平线金色闪光，周围像素汇聚，进度即时变化；真实应用时触发 0.42 秒 |
| 使用 | 0.18 秒白色内框闪光，同一步多重合并视觉闪光 |

加减速并存时两种标记保留、线为中性色、按正常速度；冰冻外观优先，暂停加减速标记，仍可叠加充能。充能用独立视觉序号，不能从快速 CD 变化猜测。流光核宽 2/3/4、尾长 8/12/16；雪花半径 4/6/8，顶部 28 px 避让吊牌。装饰计时不推进战斗。

## 7. 统一配色与素材规范

项目总色表为 128 色，固定 UI 语义与绘画用色共存，以 `assets/palettes/game-128-v1.json` 为准，绘图软件可导入同目录 `.gpl`。128 是项目选择，不是行业强制标准。所有后续新增美术从色表选色；当前自动导入拦截覆盖物品 PNG，其他素材用 `tools/art_palette.py` 校验。旧素材不整体回改。

| 语义 | 底色 | 数字色 |
| --- | --- | --- |
| 攻击 | #B53240 | #F3F6FA |
| 护盾 | #F2CC60 | #10151F |
| 中毒 | #185C3A | #F3F6FA |
| 灼烧 | #D97624 | #10151F |
| 回复 | #56C675 | #10151F |

品质色：青铜 `#C28A54`、白银 `#D1D6E0`、黄金 `#EBC75C`、钻石 `#8CD9F2`。基础色：背景 `#10151F`、面板 `#101B28`、主文字 `#F3F6FA`、次文字 `#AAB4C4`、焦点 `#75BFFF`、禁用 `#667085`、错误 `#E05263`。减速使用 `#704B3A / #C98A66`。属性和品质含义按位置分开，不随页面改色，统一取自 `GamePalette`。

颜色以 sRGB #RRGGBB 记录，透明度独立。小数字对比度按 4.5:1 设计（上述组合约 5.54／11.82／7.36／5.72／8.47:1）；可读性参考 [WCAG 文字对比](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)、[非文字对比](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)、[颜色使用](https://www.w3.org/WAI/WCAG22/Understanding/use-of-color.html)，不代表全游戏合规认证。悬停文字、图标和位置辅助识别属性。

建议输出小 128×256、中 256×256、大 384×256 PNG。完整背景无需透明；如使用透明，只允许 alpha 0 或 255。新增／修改图片不可有半透明、抗锯齿或抖动派生颜色。运行时字体和透明遮罩混合不属于源素材限色。

砒霜原图以路径及 SHA 登记旧素材例外，改图后失效。14 件原本无图的迁移物品登记在 `content/migrated-items.json`，可暂留空，补图后正常校验。新 ID 不能借用缺图豁免。

### 图片规范工具

双击 `content/normalize_item_image.cmd`，选择单帧 PNG/JPEG/WebP/BMP → 选小中大 → 对比构图 → 填物品 ID → 导出 → 将相对路径填 Excel。

默认最近邻等比例缩放、补 #101B28 背景；可选居中裁切填满。透明选项按阈值 128 二值化。输出映射固定色表、无抖动并校验，原图及已有输出不覆盖。替换旧图前先备份移走。工具不改 Excel，也不能把普通插画自动变成精良像素画。

需 Python、Pillow、tkinter；本机启动器优先已有环境，其他机器可设 `ITEM_IMAGE_PYTHON`。命令行：`python godot_prototype/tools/normalize_item_image.py 原图.png --size small --output godot_prototype/assets/items/icons/新物品.png`；`--fit cover` 裁切，`--transparent` 二值透明。

## 8. 新增物品操作与验收

| 步骤 | 入口 | 完成标准 |
| --- | --- | --- |
| 1 | normalize_item_image.cmd | 图片尺寸、色表、轮廓和构图正确 |
| 2 | items.xlsx | 总表、四品质、效果数值、所需渠道完整；保存关闭 Excel |
| 3 | check_items.cmd | 只校验通过，检查预计新增／修改／删除 |
| 4 | update_items.cmd | 模板补齐并正式更新成功 |
| 5 | view_item_report.cmd | 报告时间正确且状态“已更新工程” |
| 6 | preview_items.cmd | 搜索物品，核对四品质、悬停、10 秒真实战斗、购买装备 |
| 7 | 正式游戏 | 检查自然渠道、品质交集及关联机制；重启加载，运行中不热更新 |
| 8 | archive_items.cmd | 验收后归档已同步的配置和素材 |

这些入口位于 `content/`。仅改数值从步骤 2 开始。基础模板无需手填效果配置；追加属性在效果数值追加行。默认图片路径 `assets/items/icons/{ID}.png`。填写辅助总表至第 104 行，其他主要表至 204 行；超出复制有样式／验证的行，保持表头。基础工具需 Python 3.9+ 标准库，图片工具另需上述依赖。Godot 默认 `D:/Godot/Godot_v4.7.2-stable_win64_console.exe`，可设 `GODOT_CONSOLE`。

只校验不会应用或补写。报告只展示首个错误及单元格，修正后重跑；`reports/latest.html/json` 会覆盖，务必核对时间。报告保存失败不影响成功更新，不把旧报告当新结果。预览入口会正式更新再扫描资源，失败不打开旧数据。

通用预览只测试所选物品与无装备靶子，固定商店额外 500 测试货币，不改变正式渠道；不替代多物品联动、敌方控制及完整试炼验收。专项预览为 preview_item_frames/stats/motion/growth.cmd，砒霜固定预览为 preview_poison_vial.cmd。
