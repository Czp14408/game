## 版本管理规则

1. 一个主题只维护一份当前权威规范。文件开头记录状态、适用范围、最后确认日期、上位文档及实现状态。
2. 区分“需求已确认”“工程已接入”“人工已验收”。接入记录写明提交、环境、验证结果和未完成项；不把测试通过写成完整功能交付。
3. 规则更新时，将生效内容写入当前规范；被合并的重复草案移除并修复引用。历史验收快照、原始素材和备份保留，不用新结果覆盖旧证据。
4. 根目录只放长期适用的设计规范与必要的工程入口。阶段需求、计划、验证、素材和工作流分别放在 `docs/` 下的对应目录或素材所在目录。
5. 移动或改名后，检查文档链接、脚本引用和交付包内的文档复制路径。
